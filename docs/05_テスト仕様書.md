## 1. 方針

| 区分 | 方法 |
|------|------|
| フロー | 生成した定義をパッケージで取り込み、実際の環境で動かす。FLW-001 は詳細画面の「実行」で引数を入れて呼ぶ。FLW-002 は FLW-001 の申請から、FLW-003 はテスト用の記録（`tools/seed-test-loans.js`）を作ってから手動で動かす。FLW-004 は Forms の回答、FLW-006 は故障報告の対応状況の変更、FLW-005 は手動の実行で動かす |
| 画面 | 3画面の YAML を Studio に貼り付けて組み立て、プレビューと公開後のアプリで操作する |
| 結果の確かめ方 | フローの応答・実行の履歴、SharePoint のリストを REST で読んだ値、受信トレイ、Teams のチャンネル、Planner のボード、CSV の中身 |

- 環境: Microsoft 365 Business Standard のデモのテナント、既定の環境。社内のユーザーは1人（申請者・承認者・管理者を兼ねる）。データはすべて架空。
- 実施日: 2026-11-17（TC-001〜TC-030）、2026-11-18（TC-031〜TC-033）。日付の欄の T1 などは、実施日の翌日からの日数。

## 3. 未実施の項目と理由

| 項目 | 理由 | 実施する場合の方法 |
|---|---|---|
| 承認の7日の期限切れ（FLW-002 の TimedOut の分岐） | 7日待つ必要がある | 本番の前に、定義の期限を短くした写しで確かめる |
| 承認を始めないまま1日過ぎた承認待ち（FLW-003 の後始末の一方） | 承認依頼が必ず出るため、この状態を作れなかった | テスト用の記録を、承認開始日時を空・作成日時を2日前の形で作る |
| メンバーの権限での書き込みの失敗、メンバーが FLW-001 だけを使えること | 社内のユーザーが1人 | 2人目のユーザーをメンバーにし、REST の書き込みとアプリの操作を試す |
| 要求ヘッダー `x-ms-user-email` を利用者が書き換えられないこと | 公式の文書で確かめられず、試す手段も無い | 04 権限設計の残るリスクを参照 |
| 2件の同時の申請 | 手動では同時に送れない | 2人の利用者で同時に申請する、またはフローの実行を並べて送る |
| 予約表が多い備品での申請の画面の表示（委任の警告7件） | データが20件 | 委任できる条件に書き換えるか、件数の上限を確かめる |

## 4. 見つかって直した点

| 見つかった所 | 内容 | 直し方 |
|---|---|---|
| FLW-005（TC-025） | 明細が0件のとき、CSV に列名の行が出ない | 0件のときも列名の行を出す |
| 画面（scrMine） | 取り消すボタンの表示条件で、文字列どうしを `>` で比べていた（数式のエラー） | `DateValue(ThisItem.start) > Today()` に変更 |
