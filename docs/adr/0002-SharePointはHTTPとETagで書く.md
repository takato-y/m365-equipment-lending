## 状況

貸出記録の状態は、利用者の操作（FLW-001）・承認（FLW-002）・毎朝の処理（FLW-003）の3つから書き換えられる。取消と承認の結果、承認と期限切れが同時に起きると、後から書いた方が前の結果を消してしまう。SharePoint コネクタの「項目の更新」は、読んだ後に別の処理が変えたかどうかを確かめずに上書きする。

## 決定

- SharePoint の読み書きは、すべて「SharePoint に HTTP 要求を送信します」で REST API を呼ぶ。
- 状態を書き換えるときは、直前に読み直した記録の ETag を `If-Match` に付けて MERGE する。一致しなければ書き換えず、失敗時の処理で処理ログに残す。
- 申請は「確認中」で記録を作り、作った後にもう一度重なりを確かめる。自分より ID が小さい重なる記録があれば、自分を却下にする。

## 理由

- ETag の照合で、確認した後に別の処理が変えた記録を上書きしない。
- REST で列の内部名を直接書くため、コネクタの画面で列を選び直す作業がなく、定義をコードで生成できる（ADR 0001）。
- 先に作られた記録を優先する規則にすると、同時の申請の両方が承認待ちになることを防げる。

## 影響

- 列の内部名（`LoanStatus` など）を定義に書くため、リストを `tools/provision-lists.js` 以外の方法で作ると動かない。
- ETag が一致しないときは処理を止めて記録するだけで、自動ではやり直さない。運用で処理ログを確かめる（障害対応手順書）。
