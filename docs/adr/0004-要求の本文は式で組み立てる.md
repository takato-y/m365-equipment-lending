## 状況

SharePoint への HTTP 要求の本文（JSON）に、利用目的などの自由入力を `"Purpose": "@{...}"` の形で埋め込むと、入力に `"` や `\` が含まれたときに JSON が壊れる。`", "LoanStatus": "貸出中` のような入力で、別の列を書き換えられるおそれもある（注入）。同じく、検索の条件（`$filter`）に文字列のまま連結すると、条件を書き換えられる。

## 決定

- 要求の本文は、`setProperty(setProperty(json('{}'), '列', 値), …)` の式で、オブジェクトとして組み立てる（`tools/gen_flows.py` の `object_expr`）。
- 検索の条件に入れる値は、ID は整数に変換し、文字列は `'` を重ねてから入れる。URL に入れる値はエンコードする。
- 操作の種類はアプリから受け取った値を、決まった4つの値と照合してから使う。

## 理由

- 式で組み立てた値は、JSON の文字列として正しくエスケープされるため、入力の内容で本文の構造が変わらない。
- FLW-001 のテストで、`"`・`\`・改行と、状態・申請者の列を書き換える形の文を含む目的を送り、状態と申請者が書き換わらず、目的の列に文がそのまま入ることを確かめた。FLW-004 のテストで、`#`・`%27`・`&`・`'` を含む管理番号を送り、要求が壊れず報告が保存されることを確かめた（05 テスト仕様書）。

## 影響

- 定義の式が長くなり、画面で読むのは難しい。生成元の `tools/gen_flows.py` で読む・直す前提にする。
