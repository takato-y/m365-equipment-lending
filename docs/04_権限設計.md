## 1. ロール

| ロール | 実体 | 人 |
|---|---|---|
| 管理者 | Teams のチーム（Microsoft 365 グループ）の所有者 | 総務部の担当者（2人以上） |
| 社員 | チームのメンバー | 備品を借りる人 |
| 承認者 | 設定「承認者メール」の宛先 | 上長または総務部の責任者 |
| フローの接続 | フローの所有者（管理者の1人）の接続 | — |

## 2. 権限表

| 対象 | 管理者 | 社員 | 決め方 |
|---|---|---|---|
| 備品台帳（LST-001） | 編集 | 閲覧 | リストの権限の継承を切って付け直す |
| 貸出記録（LST-002） | 編集 | なし | 同上。利用目的・承認コメントを含むため |
| 故障報告（LST-003） | 編集 | なし | 同上。報告者と内容を含むため。**対応状況の変更が修理の完了の入口**になる（ADR 0003） |
| 設定（LST-004） | 編集 | 閲覧 | 同上。画面が上限日数を読むため。秘密の値は置かない |
| 処理ログ（LST-005） | 編集 | なし | 同上 |
| 予約表（LST-006） | 編集 | 閲覧 | 同上。備品・期間・状態だけ |
| 月次レポート（LIB-001） | 編集 | なし | 同上 |
| アプリ | 共同所有者 | 利用者として共有 | アプリの共有 |
| FLW-001 | 所有者 | アプリから実行だけ（所有者の接続で書き込む） | アプリに追加したフローを、アプリの利用者が所有者の接続で実行する想定（2人目のユーザーでは未確認。5章） |
| FLW-002〜006 | 所有者 | なし | 共有しない |
| Planner のプラン | 編集 | 編集（チームのメンバーは編集できる） | 備品の状態の入口にしない（ADR 0003） |
| Forms のフォーム | 編集 | 回答だけ（組織内の人だけ、名前を記録） | フォームの設定 |
| Teams のチャンネル | 投稿・閲覧 | 閲覧 | カードには、故障の内容・報告者・利用目的を載せない |

- 権限の継承の切り離しと付け直しは `tools/provision-lists.js` が行い、付け直した後に読み直して確かめる。
- 社員はリストに書き込めないため、書き込みはすべて FLW-001（申請・返却・取消）と FLW-002〜006 が行う。

## 3. 書き込みの入口ごとの確認

| 入口 | 確かめること |
|---|---|
| FLW-001 申請 | 呼び出したユーザー（要求ヘッダーから確定した SharePoint のユーザー ID）を申請者にする。備品・期間・目的を検証し、重なりを作成の前後で2回確かめる |
| FLW-001 返却・取消 | 対象の記録の申請者 ID が呼び出したユーザーと一致し、状態が対象の状態であること。ETag の照合つきで書く |
| FLW-002 承認 | 応答した人が申請者本人で、設定「自己承認を許可」が「いいえ」なら却下。結果を書く前に記録がまだ承認待ちか確かめる |
| FLW-004 故障の受付 | 備品台帳は変えない。管理番号は整えてから検索の条件に入れる |
| FLW-006 対応状況の反映 | 故障報告を編集できるのは管理者だけ。備品の状態は修理中の報告の件数で決める |

## 4. デモの環境での扱い

| 項目 | デモの環境 | 本番の推奨 |
|---|---|---|
| 社内のユーザー | 1人（申請者・承認者・管理者を兼ねる） | 管理者2人以上、承認者は申請者と別の人 |
| 自己承認を許可 | はい | いいえ（既定） |
| フローの接続 | 本人の接続 | 管理者の1人の接続。共同所有者を置き、退職・異動のときに接続を付け替える |
| 環境のシステム管理者 | 本人を追加した（ADR 0001 の設定の変更のため） | 必要な期間だけ付ける |

## 5. 残るリスク

| リスク | 内容 | 対策・扱い |
|---|---|---|
| 要求ヘッダーのなりすまし | FLW-001 は呼び出したユーザーを要求ヘッダー `x-ms-user-email` から取る。利用者がこのヘッダーを書き換えて送れないことは、公式の文書でも試験でも確かめていない（要検証） | ヘッダーの値を SharePoint のユーザーとして確定し、メールか UPN が一致するときだけ進める。本番の前に、別のユーザーでフローを直接呼んで確かめる |
| メンバーの権限の分離 | 社内のユーザーが1人のため、社員の権限で書き込めないことを実際には確かめていない | 本番の前に、2人目のユーザーで確かめる（05 テスト仕様書 3章） |
| 承認依頼が残る | 取消しても承認依頼は残る。後で応答されても結果は書かないが、承認者の一覧には残る | 承認者に、取消済みの依頼が残りうることを伝える |
| 所有者の接続への依存 | 所有者のアカウントが無効になると、全フローが止まる | 共同所有者を置き、接続の付け替えの手順を 06 に書く |
| Planner の編集 | メンバーはタスクを完了にできる | 備品の状態には影響しない。タスクの状態と故障報告の対応状況が食い違ったら、故障報告を正とする |
