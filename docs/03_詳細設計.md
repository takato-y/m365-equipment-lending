## 2. フローに共通する作り

### 2.1 処理の枠

```text
変数の初期化・今日（日本時間）
試行（Scope）
  設定の取得 → 設定を1つのオブジェクトにする
  本体の処理
失敗時（試行が失敗・タイムアウト・取消のときに動く）
  失敗した手順の名前とエラーの種類だけを取り出す
  処理ログに記録（結果＝失敗）
  管理者メールが空でなければ、管理者にメール
```

- 処理ログの「詳細」には、手順の名前とエラーの種類だけを書く。利用目的・氏名・メールアドレスは書かない。
- FLW-003 は4つの処理（開始日の切り替え・お知らせ・督促・後始末）を独立した範囲にする。範囲の状態は最後の手順で決まるため、失敗時の処理は常に動かし、中のどれかが失敗していたときだけ記録と通知をする。
- FLW-001 は、失敗時にもアプリへ必ず応答を返す（「処理に失敗しました。…」）。作りかけの「確認中」の記録は、ETag の照合つきでエラーにし、その予約表の行を消す。

### 2.2 SharePoint の読み書き

| 操作 | 書き方 |
|---|---|
| 読む | `GET _api/web/lists/getbytitle('<リスト>')/items?$select=…&$filter=…`。ETag が要るときは `odata=minimalmetadata` で受ける |
| 作る | `POST …/items`。本文は `setProperty` の式で組み立てる（ADR 0004） |
| 状態を変える | `POST …/items(<ID>)`、`X-HTTP-Method: MERGE`、`IF-MATCH: <読んだ ETag>`（ADR 0002） |
| 予約表をそろえる | 貸出記録の ID を件名に持つ行を探し、状態を変えるか消す（`IF-MATCH: *`） |

- 列は内部名（`LoanStatus`・`StartDate` など）で書く。表示名と内部名の対応は `tools/provision-lists.js`。
- 検索の条件に入れる値は、ID は `int()`、文字列は `'` を重ねる。URL に入れる値は `encodeUriComponent` を通す。

### 2.3 日付

- 「今日」は `convertFromUtc(utcNow(), 'Tokyo Standard Time')` の日付。
- 開始日・返却予定日は、日本時間の0時を UTC にして保存する（`convertToUtc(concat(日付,'T00:00:00'),'Tokyo Standard Time')`）。
- 空の日時を比べるときは、既定の日時に置き換えてから `ticks` で比べる（評価の順序に頼らない）。

### 2.4 実行の記録に残さない値

| フロー | 隠す対象 |
|---|---|
| FLW-001 | トリガーの出力（引数と要求ヘッダー）、入力、記録の作成、自分の記録、一覧の整形 |
| FLW-002 | トリガーの出力、記録の読み直し、承認 |
| FLW-003 | 予約済み・貸出中・承認待ち・確認中の取得 |
| FLW-004 | トリガーの出力、回答の詳細、報告者の確認、故障報告の作成 |
| FLW-005 | 前月の貸出 |
| FLW-006 | トリガーの出力 |

- 作成（Compose）・選択（Select）・Query は `inputs` だけを隠す（`outputs` を指定すると取り込みで拒まれる）。

### 2.5 呼び出したユーザーの確定（FLW-001）

1. トリガーの要求ヘッダー `x-ms-user-email` を小文字にする。空なら「利用者を確認できませんでした。会社のアカウントでアプリを開いてください。」を返す。
2. `_api/web/ensureuser` で SharePoint のユーザーにする。
3. 確定したユーザーのメールか UPN が、手順1の値と一致するときだけ進める。一致しなければ「利用者を確認できませんでした。管理者に連絡してください。」を返す。
4. 以後の本人の判定は、SharePoint のユーザー ID（`RequesterId`、整数）で行う。

## 3. FLW-001 の入力と応答

### 3.1 入力（Power Apps から渡す引数）

| 引数 | 型 | 内容 | 検証 |
|---|---|---|---|
| text | 文字列 | 操作の種類 | 申請／一覧／返却／取消 のどれか。違えば「この操作は受け付けていません。」 |
| text_1・text_2 | 文字列 | 開始日・返却予定日（yyyy-MM-dd） | 10文字の日付の形、開始日は今日以降、返却予定日は開始日以降、期間は貸出上限日数以内、開始日は予約受付日数以内 |
| text_3 | 文字列 | 利用目的 | 前後の空白を除いて 1〜500文字 |
| number | 数値 | 備品の ID | 1以上の整数 |
| number_1 | 数値 | 貸出記録の ID（返却・取消） | 整数 |

### 3.2 応答（アプリが表示する）

| result | message | 場面 |
|---|---|---|
| 受付 | 申請を受け付けました。承認の結果はメールでお知らせします。 | 申請が通った |
| 却下 | 入力の内容（期間・目的）を確かめてください。貸出は最長 N 日、開始日は今日から N 日先までです。 | 入力の検証に落ちた |
| 却下 | この備品は今は貸し出せません。 | 備品が利用可でない |
| 却下 | 同じ期間に、ほかの申請・予約があります。期間を変えて申請してください。 | 作成の前の重なりの確認 |
| 却下 | 同じ期間に、ほかの申請があります。期間を変えて申請してください。 | 作成の後の再確認で、先の申請があった |
| ok | 返却を登録しました。／取り消しました。 | 返却・取消が通った |
| 却下 | この記録は返却できません。…／取り消せません。… | 本人の記録でない、または状態が合わない |
| エラー | 利用者を確認できませんでした。… | 2.5 の手順1・3 |
| エラー | 処理に失敗しました。時間をおいてもう一度お試しください。続く場合は管理者に連絡してください。 | 失敗時の処理 |

- 「一覧」の応答の data は、本人の記録（最大100件、新しい順）の JSON 文字列。項目は id・equipment・start・due・status・note。利用目的は返さない。

## 4. 画面

| 画面 | 主なコントロール | 主な数式・動き |
|---|---|---|
| scrEquipment（SCR-001） | ddCategory・txtSearch・galEquipment・btnMine・btnRefreshList | 一覧は `Filter(備品台帳, 区分・検索語)` を管理番号の順に並べる。「申請する」は状態が利用可のときだけ出し、押すと varEquip に備品を入れて入力を初期化し、scrApply へ。「最新の状態にする」は備品台帳と予約表を読み直す |
| scrApply（SCR-002） | dpStart・dpDue・txtPurpose・lblCheck・btnApply・galResv | lblCheck が入力の誤りを1つずつ表示し、空のときだけ「申請する」を押せる。上限日数・予約受付日数は設定リストから読む（無ければ 14・60）。押すと FLW-001 の「申請」を呼び、受付なら一覧へ戻る。galResv は予約表の、この備品の今後の期間 |
| scrMine（SCR-003） | galMine・btnReload・btnReturn・btnCancel | FLW-001 の「一覧」の data を colMine に入れて表示する。「返却した」は貸出中のとき、「取り消す」は承認待ち・予約済みで開始日が明日以降のときに出す。押した後は一覧を読み直す |

- フローを待つ間は varBusy で全ボタンを押せなくする。フローの呼び出しが失敗したときは IfError で決まった文を表示する。
- 委任の警告が7件ある（galEquipment 4件・galResv 3件）。備品は数十件、予約表は終わった行を消すため、件数の上限（既定 500）に届かない前提とする。
