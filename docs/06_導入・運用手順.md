## 1. 前提

| 項目 | 内容 |
|---|---|
| ライセンス | Microsoft 365 Business Standard 相当（Power Apps・Power Automate は標準コネクタだけを使う） |
| 作業する人 | 導入先のテナントで、チームを作れ、既定の環境でアプリとフローを作れる人。手順 2.2 の設定の変更には、環境のシステム管理者の権限が要る場合がある |
| 手元の道具 | Python 3.10 以上（パッケージの作成）、ブラウザー |

## 2. 導入手順

### 2.1 チームとフォームを作る

1. Teams でチーム（例: 備品貸出管理）を作り、通知用のチャンネルを作る。管理者を所有者、社員をメンバーにする。
2. Planner で、チームのプラン「備品の修理対応」を作り、バケット「確認待ち」「修理中」を作る。
3. Forms で、チームのフォーム「故障・不具合の報告」を作る。質問は「管理番号」（テキスト）と「内容」（長いテキスト）。組織内の人だけが回答でき、名前を記録する設定にする。

### 2.2 環境の設定

- 既定の環境で、ソリューションの書き出し・取り込みが使えるかを確かめる。使えない場合は、Power Platform 管理センターの環境の設定で「Dataverse ソリューションで作成する」をクラウド フロー・キャンバス アプリともオフにする（[ADR 0001](adr/0001-パッケージで取り込む.md)）。

### 2.3 リストを作る

1. チームの SharePoint サイトで「サイトの設定」（`/_layouts/15/settings.aspx`）を開く。
2. ブラウザーの開発者ツールのコンソールに `tools/provision-lists.js` の中身を貼り付けて実行する。リスト6つとライブラリ1つ、権限、設定7件、架空の備品20件ができる。
3. 「設定」リストの「承認者メール」「管理者メール」を入れる。本番では「自己承認を許可」を「いいえ」のままにする。

### 2.4 フローを取り込む

1. `private/config.local.json` を作り、次の値を入れる（`private/` は `.gitignore` で除外している。値は公開しない）。

   | キー | 値 |
   |---|---|
   | SITE_URL | チームのサイトの URL |
   | LIST_LOANS_ID・LIST_FAULTS_ID | 貸出記録・故障報告のリストの ID |
   | TEAM_ID・CHANNEL_ID | チームとチャンネルの ID |
   | PLAN_ID・BUCKET_ID | プランと「確認待ち」のバケットの ID |
   | FORM_ID・Q_CODE・Q_DETAIL | フォームの ID と、2つの質問の ID |

2. パッケージを作る（フローごと）:
   ```bash
   python3 tools/gen_flows.py
   python3 tools/build_package.py flows/FLW-001.json -c private/config.local.json -o private/pkg/FLW-001.zip
   ```
3. Power Apps の「アプリ」→「アプリをインポートする」→「パッケージから (.zip)」で取り込む。初回は「新しく作成する」、2回目からは「更新」で同じ名前のフローを選ぶ。接続は既にある接続を選ぶ。
4. 取り込んだ後、フローはオフになっているので、オンにする（更新したときも同じ）。

### 2.5 アプリを作る

1. Power Apps でタブレットの形の空のキャンバス アプリを作り、データに 備品台帳・予約表・設定 を、フローに FLW-001 を追加する。
2. 画面を3つ（scrEquipment・scrApply・scrMine）にし、各画面を選んで `app/*.yaml` の中身を Ctrl+V で貼り付ける。
3. 「アプリのチェック」でエラーが0件であることを確かめ、保存して公開し、社員に共有する。

### 2.6 導入時の確認

- 05 テスト仕様書の TC-028（申請→取消）、TC-009（承認）、TC-020（故障の報告）を、架空のデータで1回ずつ行う。
- 確かめた後、テストの記録を消し、架空の備品を実際の備品に入れ替える。

## 3. 日々の運用

| いつ | 何をする | 見る所 |
|---|---|---|
| 毎日 | 承認依頼に応答する | Teams の「承認」、メール |
| 毎日 | 故障の報告を確かめ、対応状況を「修理中」「完了」「対象外」に変える（**Planner ではなく故障報告リストで変える**） | 故障報告リスト、Teams のカード |
| 毎週 | 処理ログに「失敗」が無いか確かめる | 処理ログ |
| 毎月1日 | 月次の集計のメールと CSV を確かめる | メール、月次レポート |
| 毎月 | 6本のフローがオンのままか確かめる（長く動かないフローは止められることがある） | Power Automate の「マイ フロー」 |
| 年に1回 | 処理ログの1年より古い行を消す | 処理ログ |

## 4. 設定の変え方

- 上限日数・予約受付日数・督促上限回数・宛先は、「設定」リストの値を変えるだけでよい（次の実行から使われる）。
- 承認の期限（7日）はフローの定義に固定している。変える場合は `tools/gen_flows.py` の `P7D` と FLW-003 の後始末の日数を直し、FLW-002・FLW-003 を作り直して「更新」で取り込む。

## 5. フロー・画面を直すとき

1. `tools/gen_flows.py` または `app/*.yaml` を直す。
2. フローは 2.4 の手順で作り直し、「更新」で取り込み、オンにする。画面は該当する画面の部品を消して貼り直す。
3. コミットの前に `python3 tools/check_public_safety.py --staged` を実行する（`git config core.hooksPath .githooks` で自動にできる）。

## 6. 担当者の交代

| 交代する物 | 手順 |
|---|---|
| フローの所有者 | 新しい担当者を各フローの共同所有者に加え、接続を新しい担当者の接続に付け替える。前の担当者を外す |
| アプリの所有者 | 新しい担当者を共同所有者にする |
| 承認者・管理者 | 「設定」リストのメールアドレスを変える |
| チーム | 新しい担当者を所有者に加え、前の担当者を外す |

## 7. バックアップと戻し方

- 定義（フロー・画面・リストの作成）はリポジトリにある。作り直すときは 2章の手順で再現できる。
- データ（リストの中身）は SharePoint のごみ箱とバージョン履歴で戻す。定期的な控えが要る場合は、月次の CSV に加えてリストを Excel に書き出す。
